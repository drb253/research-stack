# Tables and Figures

## The provenance gate

A display may be generated only from data that exists in a ledger or that the user supplied
directly. Before a display enters the manuscript, every one of these must be answerable:

- stable display ID and version, matching the in-text reference;
- the `S` IDs (and `C` IDs) it draws on;
- the command or transformation that produced it;
- the analysis population, denominators, and time points;
- units and the definition of any uncertainty shown;
- who created it and who checked it, with dates;
- for reused material: licence, attribution, and permission status.

Never recreate missing values from a screenshot, a published figure, or an abstract's text. Never
redraw a published figure and present it as your own. Never generate an illustrative image and label
it as data. If a display cannot be sourced, it does not go in the review.

## Choosing the form

| Use | When |
|---|---|
| Prose | One or two values, directly relevant; a display would be overhead |
| Table | Exact values and multi-dimensional comparison matter (designs, populations, effects) |
| Figure | Pattern, distribution, relationship, sequence, or flow matters |
| Flow diagram | The reader must see how records moved from search to inclusion |
| Conceptual diagram | The framework is the contribution; caption it as explanatory, not as data |

Do not duplicate the same information in prose, a table, and a figure. One home per fact; the prose
interprets, it does not repeat.

## Standard tables for a medical narrative review

**Table 1 — Study characteristics / evidence table.** One row per included source. Columns: source
ID, first author and year, design, population, intervention or exposure, comparator, n, follow-up,
outcomes, main finding, effect estimate, verification.

```bash
python3 scripts/make_evidence_table.py sources.csv --style evidence-table \
  --group-by theme --out tables/table1.md
```

**Table 2 — Certainty of evidence by theme.** One row per theme: number of included sources, summed
participants (only from reported n), highest certainty, direction of evidence, designs, and recorded
caveats (non-peer-reviewed material, preprint evidence, expression of concern).

```bash
python3 scripts/make_evidence_table.py sources.csv --style certainty-of-evidence \
  --claims claims.csv --out tables/table2.md
```

**Table 3 — Excluded records with reasons.** Required when the review has a systematic search
component; belongs in the appendix and mirrors the eligibility box of the flow diagram.

```bash
python3 scripts/make_evidence_table.py sources.csv --style excluded-log --out tables/table3.md
```

Additional tables worth considering when the material demands them: guideline recommendations with
dates and evidence grades; ongoing trials with registry IDs, phase, and status; a safety-signal table
separating randomised from observational data.

## Figure 1 — the screening flow

```bash
python3 scripts/make_prisma_flow.py prisma_counts.json --out-dir figures/
```

Produces SVG (for the manuscript), Mermaid (for Markdown and review workflows), and a Markdown
caption block. The command refuses to draw unless the counts balance arithmetically, so the figure
cannot contradict the screening log. Caption it "adapted from PRISMA 2020" only if the review
genuinely followed a PRISMA-style process; otherwise caption it "screening flow", because a PRISMA
diagram in a narrative review implies an exhaustiveness the review may not have.

## How the figure reaches each delivery format

| Format | How the flow diagram gets in | Fidelity |
|---|---|---|
| PDF | Drawn as **vectors** by `export_document.py` from `prisma_counts.json`, with the counts checked arithmetically first | Sharp at any zoom; text is selectable |
| HTML | The generated `figures/prisma_flow.svg` is embedded with `<img>` | Sharp; SVG is native to browsers |
| DOCX (Word) | A PNG is embedded. Supply one, or let the exporter convert the SVG with `rsvg-convert`, `inkscape`, `magick`, or macOS `qlmanage`. Without any rasteriser the DOCX carries a labelled placeholder naming the figure file, and the SVG is delivered beside it | 2,000 px wide raster, width-scaled to the text column |

Word cannot render an SVG through a plain picture reference, so the DOCX path deliberately embeds
raster bytes and names the media part with the real extension. If the DOCX ever shows a broken picture,
check `images_embedded` in the export report and the `EXPORT_NOTE` issues: the exporter states plainly
when a figure could not be embedded rather than shipping a silent gap.

Figure and table numbering follows the text. Cite `Figure 1` and `Table 1` in order, and keep the same
identifiers in Markdown, DOCX, PDF, and HTML so a co-author reading the Word file and a reviewer reading
the PDF are looking at the same display. Appendix tables generated by `make_evidence_table.py` carry
their own captions and are appended in the export step with `--append`.

## Other permitted figures

- **Conceptual or thematic framework** built from the review's own claim clusters, captioned as an
  explanatory synthesis and not as data.
- **Mechanistic schematic** drawn from cited sources, with each step carrying its citation numbers.
- **Forest-style plot** *only* when reproducing reported effect estimates, with a caption stating
  explicitly that no pooling was performed and that the display shows reported estimates with their
  own intervals. Never compute a pooled estimate, and never re-compute an interval.
- **Timeline** of trial readouts or guideline updates, from dated sources.
- **Descriptive count plots** from the ledgers (designs, years, themes) with no significance marks.

## Prohibited in displays

- Significance stars or "p < 0.05" annotations without a verified test behind them.
- Trend lines fitted to values you did not extract from a reported analysis.
- Truncated axes that exaggerate differences without an explicit break marker and note.
- 3D bars, shadowed graphics, or pie charts with more than five slices.
- Colour as the only encoding; add shape, pattern, or direct labels.
- Any number not present in `sources.csv` and reachable from a `C` ID.
- Preprints, abstracts, or modelling outputs merged into a table of trials without a label column.


## Captions

A caption states, in this order:

1. what is shown and in which population;
2. the design of the contributing studies and the number of sources;
3. units, denominators, and the definition of any uncertainty;
4. abbreviations used in the display, expanded;
5. the source IDs or citation numbers behind the display;
6. for figures derived from other work: attribution and permission.

Example caption:

```text
Table 1. Characteristics of included studies. NSCLC, non-small-cell lung cancer; RCT,
randomised controlled trial; HR, hazard ratio; CI, confidence interval. Effect estimates are
reported as published; no pooling was performed. "Verified" refers to the DOI/PMID check and
source-locator review recorded in sources.csv.
```

## Accessibility and alt text

- Provide alt text for every figure: describe what is shown and the main pattern, not the numbers.
- Keep tables as real tables (Markdown or Word tables), never as images.
- Use colour-blind-safe palettes, high contrast, and redundant encoding.
- Keep the smallest font in a figure at least 7-8 pt at final print size.
- Export at the venue's required resolution (usually 300 dpi raster; vector for line art).

## Final display checklist

- [ ] Every table and figure is referenced in the text, and every in-text reference resolves to a
      caption (`TABLE_REFERENCE_WITHOUT_CAPTION` and `FIGURE_REFERENCE_WITHOUT_CAPTION` fail otherwise).
- [ ] Every caption is referenced at least once in the text (`CAPTION_NEVER_REFERENCED_IN_TEXT`).
- [ ] Values in displays match the prose, the abstract, and `sources.csv`.
- [ ] Percentages recompute from the reported numerator and denominator.
- [ ] Missing values display as `not_reported`, never as blank or zero.
- [ ] Abbreviations in every caption are expanded at first use.
- [ ] The number of displays is within the venue's limit.
- [ ] Each display has a provenance record listing its source IDs and generating command.
- [ ] Tables are numbered in the order they are first cited in the text.
